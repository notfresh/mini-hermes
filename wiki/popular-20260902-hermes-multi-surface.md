# Hermes 的多张脸：一个大脑，四种皮肤

> hermes 科普系列·第一篇。从一个真实早晨讲起，把 Hermes 的"多端架构"讲成大白话。源码导航附文末。

## 开场：同一个 /ss，三种命运

假设你在三个地方敲同一个命令 `/ss`（一个指向 `/sessions` 的快捷别名）：

- 在 **CLI**（终端里敲 `hermes`）里敲 → 打印一张**纯文本列表**
- 在 **TUI**（花哨的终端界面）里敲 → **弹出会话选择器**，上下键选
- 在**飞书**里 @ 机器人发 `/ss` → 机器人回你一段话

同一个 Hermes、同一个别名、同一个 `/sessions`，为什么表现完全不同？

如果这是三个不同的软件，你一点都不惊讶。但它们是**同一个软件**——这就是 Hermes 多端架构最反直觉的地方，也是理解 Hermes 的第一把钥匙。

## 一句话架构

> **Hermes = 一个大脑（agent core）+ 四张脸（4 种界面）**

大脑是那个真正会思考的部分：对话循环、工具调用、技能加载、记忆读写——它**没有界面**，不知道自己是跑在终端还是飞书里。

四张脸是皮肤，负责把用户的话递进大脑、把大脑的话渲染出来：

| 脸 | 形态 | 交互 |
|---|---|---|
| **CLI** | 终端里的 REPL（`hermes`） | 敲命令，看文本 |
| **TUI** | 富终端界面（`hermes --tui`） | 面板、选择器、补全下拉 |
| **Desktop** | Electron 桌面应用 | 鼠标点、窗口 |
| **Gateway** | 消息平台机器人（飞书/Telegram/Discord 等 20+） | 聊天消息 |

四个脸是**四个独立进程**，各跑各的；但聊到同一个话题时，它们背后是同一个大脑逻辑、同一份配置、同一个会话库。

## 它们靠什么"是同一个 Hermes"？

三样东西把四张脸焊在一起：

**1. 一份全局配置（config.yaml）**

所有脸读同一个 `~/.hermes/config.yaml`。你在里面加一行：

```yaml
quick_commands:
  ss:
    type: alias
    target: /sessions
```

CLI、TUI、飞书立刻都认识 `/ss`——不用给每个脸单独配。模型、技能、记忆也是同一套。

**2. 一个共享的会话库（SQLite）**

所有脸的对话记录进同一个数据库，但每条记录都盖一个章，叫 **source**（来源）：

```
source    条数
cron      468   ← 定时任务自己跑的快照
feishu    209   ← 飞书里的对话（你现在这条就是）
cli        52   ← 经典终端
tui        39   ← 富终端界面
```

这个章就是"会话隔离"的根据（下面讲）。

**3. 一套统一注册的命令表（COMMAND_REGISTRY）**

所有脸的斜杠命令都从同一张注册表登记——但**执行方式各脸自由**。这正是开场那个谜的答案。

## 谜底：/sessions 在注册表里是一条，在每张脸上是一个实现

`/sessions` 命令只在一处登记（COMMAND_REGISTRY），保证三张脸都知道"有这么个命令"。但"显示会话列表"这件事，每张脸用自己的方式做：

- CLI 没有弹窗能力 → 打印文本列表
- TUI 有交互组件 → 弹选择器，还能上下键选
- 飞书只能发消息 → 回你一段排版好的文本

**命令的身份是统一的，命令的皮肤是各自的。** `/ss` 别名展开成 `/sessions` 之后，各脸执行的是"自己的 sessions"——所以表现不同不是 bug，是设计。

## 顺带解开今天那个困惑：为什么 CLI 里 /ss 看不到飞书的会话？

还记得上面的 source 章吗？`/sessions` 在 CLI 里默认**只列 source=cli 的会话**（"source-scoped by default"，防串台的设计）。

你的历史大多盖着 feishu 的章 → CLI 的列表里当然没有。想看全部，用 `hermes sessions list`（终端命令，不盖章过滤）；想恢复某个飞书会话，`/resume <会话ID>` 直接按 ID 找，章拦不住 ID 直查。

一句话记住：**每张脸默认只看自己来源的会话——就像每个微信账号看不到别的账号的聊天记录**。

## 为什么这么设计？

三个理由，层层递进：

1. **界面能力不同**（TUI 能弹窗，CLI 不能）→ 皮肤必须各做各的
2. **大脑要复用**（思考逻辑写一遍，四个界面共用）→ 核心必须无界面
3. **会话要隔离**（防串台、防 A 窗口读到 B 窗口的私密对话）→ 数据必须盖 source 章

代价是：你想"无缝切换界面继续同一个对话"时，要主动 `/resume` 跨来源——这是为安全付的小学费。
